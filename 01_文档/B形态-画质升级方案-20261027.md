# B 形态画质升级：给上采样加时域（TAA-lite）

> 2026-10-27 05:45　实施方案（可直接照做）
> 背景：B 形态已跑通并稳定在 53~59fps，但画质有**两个问题**——边缘锯齿、闪烁。
> 结论：两者同源，都缺"时域累积"，可以用**一个 pass** 同时解决。

---

## 一、问题定位（先确认要治什么）

| 现象 | 现状 | 根本原因 |
|---|---|---|
| **边缘锯齿** | Catmull-Rom 纯空间放大 | 1440p→4K 没有亚像素采样，高对比边缘直接阶梯 |
| **闪烁** | 残差与边缘逐帧变化 | 没有历史帧可平均，逐帧抖动全部暴露 |

真 XeSS 靠三件套解决：**jitter 亚像素 + 时域累积 + MV 重投影**。
我们现在只有 MV（传了但上采样没用），缺 jitter 和历史缓冲。

---

## 二、方案总览

在现有 `g_bUp4k` 之后插一个 **TAA-lite pass**：

```
pColor(1440p) ──Catmull-Rom──> 4K 当前帧
                                  │
  history(上一帧的 4K 输出) ──MV 重投影──> 邻域钳制 ──> 混合 ──> 4K 输出
      ↑                                                            │
      └──────────────── 存为下一帧的 history ←──────────────────────┘
```

**执行位置**：`BformBUpscale()` 之后、`BformPresentFrame()` 之前（串行路径 stage 6 里）。
流水线（stage 7）暂不用——它已被实测否掉（见 §17.8）。

---

## 三、需要新增的东西

### 3.1 A 侧：把 jitter 传过去（成本≈0）

共享 buffer 每槽已预留 **512 字节头部**（`g_upOffC = 512`，目前完全没用）。

```
做法：
  ① 建一个 256 字节的上传缓冲 g_upHdrUp（UPLOAD 堆，常驻 Map）
  ② 每帧写入：struct { float jx; float jy; uint frame; uint pad; } → Map 后 memcpy
  ③ 在 BformCopy 里，用 CopyBufferRegion 拷到 g_upBuf 的 (槽基址 + 0)
     位置：紧跟三张图的拷贝之后、状态转回 COMMON 之前
```

**注意**：`g_upBuf` 在 A 侧是 COPY_DEST 状态，`CopyBufferRegion` 可以直接用，不需要额外 barrier。

### 3.2 B 侧：读 jitter

jitter 在共享 buffer 的槽头部，是个 buffer 的一段。B 侧用**根 SRV（buffer）**读：

```cpp
// 根签名里加一个参数：D3D12_ROOT_PARAMETER_TYPE_SRV（根描述符，buffer 可以用）
// 绑定时传 GPU VA：g_upBufW->GetGPUVirtualAddress() + slot * g_upSlotBytes
cl->SetComputeRootShaderResourceView(N, addr);
```

shader 侧：
```hlsl
StructuredBuffer<float4> gHdr : register(t5);   // .x=jx .y=jy .z=frame
```

> 根描述符**只能描述 buffer**（这条我们踩过，纹理必须走描述符堆）。这里正好是 buffer，可以用。

### 3.3 B 侧：历史缓冲（2 张，ping-pong）

```cpp
// 尺寸 = 输出分辨率（4K），格式与 g_up4k 一致（B8G8R8A8），带 UAV
ComPtr<ID3D12Resource> g_taaHist[2];
```

显存：2 × 33MB = 66MB（B 有 15.8GB，无压力）。

**初始化**：第一帧没有历史 → 直接把当前帧写进 history 并输出，跳过混合（用 `g_taaInit` 标志）。

## 四、核心 shader（可直接用）

```hlsl
Texture2D<float4>   gCur  : register(t0);   // 当前帧（Catmull-Rom 放大后的 4K）
Texture2D<float4>   gHist : register(t1);   // 历史（上一帧输出，4K）
Texture2D<float4>   gMV   : register(t2);   // 运动矢量（1080p RG16F）
StructuredBuffer<float4> gHdr : register(t5); // .x=jx .y=jy .z=frame
SamplerState        gSmp  : register(s0);
RWTexture2D<float4> gDst  : register(u0);   // 本帧输出（4K）
RWTexture2D<float4> gHistOut : register(u1); // 本帧输出同时存为下一帧的 history

cbuffer P : register(b0) {
    float gAlpha;      // 混合系数：越小越稳但越容易拖影（建议 0.10~0.20）
    float gClampK;     // 邻域钳制的放宽系数（建议 1.0~1.5；越小越防拖影）
    float gMvScale;    // MV 像素→uv 的缩放（沿用 A 侧同一个值）
    float gInit;       // 1 = 第一帧，跳过混合直接输出
};

[numthreads(8,8,1)]
void main(uint3 id : SV_DispatchThreadID)
{
    uint w, h; gDst.GetDimensions(w, h);
    if (id.x >= w || id.y >= h) return;
    float2 uv = (float2(id.xy) + 0.5) / float2(w, h);

    float3 cur = gCur.Load(int3((int)id.x, (int)id.y, 0)).rgb;
    float4 outc = float4(cur, 1.0);

    if (gInit < 0.5) {
        // ── 邻域钳制：取当前帧 3x3 的 min/max，历史必须落在里面 ──
        float3 mn = cur, mx = cur;
        [unroll] for (int j = -1; j <= 1; ++j)
        [unroll] for (int i = -1; i <= 1; ++i) {
            int2 q = clamp(int2(id.xy) + int2(i, j), int2(0,0), int2((int)w-1,(int)h-1));
            float3 s = gCur.Load(int3(q, 0)).rgb;
            mn = min(mn, s); mx = max(mx, s);
        }
        float3 ext = (mx - mn) * 0.5 * gClampK;
        mn -= ext; mx += ext;

        // ── 重投影：用 MV 把历史帧对齐到当前像素 ──
        //   注意：jitter 要一起算进去，否则历史会错半像素（这是拖影/糊的主因）
        float2 jitterCur  = gHdr[0].xy;
        float2 mv = gMV.SampleLevel(gSmp, uv, 0).rg * gMvScale;
        float2 prevUV = saturate(uv - mv - jitterCur);
        float3 hist = gHist.SampleLevel(gSmp, prevUV, 0).rgb;
        hist = clamp(hist, mn, mx);                    // 钳制：抑制拖影

        // ── 混合 ──
        outc.rgb = lerp(cur, hist, gAlpha);
    }

    gDst[id.xy]     = float4(outc.rgb, 1.0);
    gHistOut[id.xy] = float4(outc.rgb, 1.0);   // 本帧结果成为下一帧的历史
}
```

**关于 jitter 的符号**：`prevUV = uv - mv - jitter` 里的 jitter 项需要实测确认正负号——
先用 `-` 试，如果边缘发糊说明符号反了，改成 `+`。

## 五、参数与调参顺序

| 参数 | 建议初值 | 调法 |
|---|---|---|
| `gAlpha` | **0.15** | 闪烁多 → 减小（更稳）；拖影多 → 增大（更贴当前帧） |
| `gClampK` | **1.2** | 拖影多 → 减小（钳得更紧）；闪烁多 → 增大 |
| `gMvScale` | 沿用 A 侧同值 | 如果重投影对不上，画面会整体"漂"，需调这个 |

**调参顺序**：先 `gMvScale`（保证对齐）→ 再 `gClampK`（压拖影）→ 最后 `gAlpha`（平衡闪烁与拖影）。

## 七、风险与已知注意点

```
· 第一帧没有历史 → 必须用 gInit 跳过混合，否则会闪一下黑/花
· 历史纹理的状态转换要严格（UAV ↔ PSR），否则会变成"读到自己正在写的内容"
· MV 的尺度如果不对，画面会整体漂移——先单独验证这一步再往下做
· 跑起来后如果出现"边缘有细黑边"→ clamp 太紧，加大 gClampK
· 如果出现"运动物体后面拖尾巴"→ gAlpha 太小 或 clamp 太松
```

## 八、为什么这样能同时治锯齿和闪烁

```
jitter：游戏渲染时每帧把采样点错开亚像素位置
        → 多帧累积后，一个像素看到的是多个不同亚像素位置的样本
        → 效果等同于"超采样" → 边缘解析出更多细节 → 锯齿减轻

时域累积：把上一帧的结果按运动矢量对齐后混进来
        → 逐帧的随机抖动被平均掉 → 闪烁减轻
```

**代价**：一次历史采样 + 一次混合 ≈ 0.5~1ms。
在 17.5ms 的基础上会变成 ~18.5ms（53fps 左右）——**画质换性能，需要你确认这个取舍**。

> 如果加完发现太慢，可先把上采样从 12 抽头降到 4 抽头补回来（约 -1ms），
> 因为有了时域累积后，空间上采样的抽头数对画质的影响会变小。
