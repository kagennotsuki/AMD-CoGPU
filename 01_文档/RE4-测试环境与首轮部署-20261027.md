# RE4 测试环境与首轮部署（2026-10-27）

> 本文记录的是一次**测试机变更**：从 RE2 换到 RE4。
> 相关文档：`MGPU-架构链路与双A替换边界-20261027.md`（上游怎么搭）、`MGPU-原样照搬落地规划-20261027.md`（抄哪些/怎么装）、`MGPU-后端与菜单参数面-20261027.md`（菜单/参数/许可/待确认）。
> 部署脚本：`08_工具与脚本\部署-MGPU到RE4.ps1`（默认演练，`-Apply` 才动手，`-Undo` 回滚）

---

## 1 · 为什么换到 RE4

| 理由 | 说明 |
|---|---|
| **RE2 要先拆自己的东西** | RE2 目录里 `libxess.dll` 是我们的跨卡 NR 代理、还有多套备份与残留（`dxgi.dll.off-amdnr-1026`、`dxgi.dll.停用-测试中`、`OptiScaler.ini` 等）。要跑 MGPU 得先停自己的 NR，事后还得恢复备份 |
| **RE4 目录干净且已具备前置** | 没有 `libxess.dll`、没有 Mochizuki 运行时；**ReShade 已装好且是 add-on 版**（详见 §2）⇒ 规划文档里的 D1 在 RE4 上**直接取消** |
| **RE4 是上游唯一验证过"无 DLSS 也有矢量"的标题** | README：*"Motion vectors for games without DLSS … Tested on Resident Evil 4 (2023)"*。我们最关键的 A2 实验（矢量到底有没有到模型）成功概率比 RE2 高得多 |
| **RE4 自带一个单卡对照基线** | 现有 `amd-nr.addon64` 用 danielblnc 运行时，可以拿它跟 MGPU 跨卡版做 A/B |

**换过来之后，"移植 libxess 上采样插件 + REFramework"这两步不需要做**：MGPU 拿的是游戏"画完之后"的帧、自己出画，**不依赖游戏的任何超分**。那两样只在"将来要靠 XeSS 代理当我们自己的 MV/jitter 源"时才需要，属备选方案。

**三条关键日志证据**

1. ReShade 版本与能力（`ReShade.log` 头部 + 注册行）：
   ```
   Initializing crosire's ReShade version '6.8.0.2155' (64-bit) loaded from '…\dxgi.dll'
   Loading add-on from '…\amd-nr.addon64' ...
   Registered add-on "AMD Neural Rendering" v0.0.0.0 using ReShade API version 20.
   ```
   ⇒ **≥6.8.0 且能加载 `.addon64`**，MGPU 的要求（API 20）正好满足。

2. 单卡 add-on 用的是 **danielblnc 的运行时**，且它的 ini 证实了 `Style` 的语义：
   > `Style: 0 = Default, 1 = Natural, 2 = Cinematic, **the same three DLSSNR.Style selects on NVIDIA**`
   ⇒ MGPU 面板的 `Style A/B/C` = 0/1/2，这一条现在有第二个来源印证。

3. **它自己承认在 RE4 上拿不到游戏矢量**（`amd-nr.log`）：
   ```
   D3D12 route: depth copied just before the game clears it;
   motion by optical flow: no game MV path on this API; Feed.fx does not reach the network here.
   ```
   ⇒ 单卡版只能**光流估运动**。而 MGPU 有一条 R280（从 RE Engine 的 RGBA16 G-buffer 抽 `.xy`）——**如果那条在 RE4 上能通，我们拿到的就是单卡版拿不到的东西**，这也是最值得先验的。

## 3 · 与 RE2 部署的差异（照抄时容易错的地方）

| 项 | RE2 当时 | RE4 现在 | 处置 |
|---|---|---|---|
| ReShade | 要装（**曾是我们唯一的硬阻塞**） | **已装，6.8.0.2155 / add-on 版** | D1 取消 |
| ReShade 代理名 | `dxgi.dll` 曾被 AMDNR 占用 | `dxgi.dll` = ReShade 本体 | 保持不动，**不装第二份** |
| `EffectSearchPaths` | 需要手改 | `.\`（只扫根目录） | **必须改成 `.\reshade-shaders\Shaders\**`**，否则 tap 编不出来 → ERROR 204 |
| `AutoSavePreset` | 要改 0 | `1` | 必须改 0（测量期防预设漂移） |
| `reshade-shaders\` | 要建 | 不存在 | 脚本会建 `Shaders`/`Textures` 并放 tap |
| 另一条神经路径 | 我们的 libxess 代理 | **`amd-nr.addon64`** | **必须停用**（改名 `.off-mgpu-<时间>`） |
| 我们自己的 NR 运行时 | 有 | 没有 | 无需拆 |

## 4 · 开工前必须做的三件事

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | **停用 `amd-nr.addon64`**（改名，不是删） | 上游明令"不要两条神经路径并行"。注意它 `StartOn=0` 但 add-on **仍会加载并注册事件**（日志：`events subscribed: mask 31`），所以必须在文件层面停用 |
| 2 | **改 `ReShade.ini`**：`EffectSearchPaths` → `.\reshade-shaders\Shaders\**`；`AutoSavePreset` → `0` | 前者决定 tap 能不能编译（深度 lane 的命门），后者防止预设被写回 |
| 3 | **存一份目录快照** | 改前备份纪律；脚本会写 `_备份-MGPU前-<时间>\backup-inventory.txt`（含 `dxgi.dll`/`amd-nr.addon64` 的 SHA256 + `ReShade.log` 头部） |

## 6 · 首轮 `mgpu.ini` 覆盖（脚本自动写）

| 键 | 值 | 理由 |
|---|---|---|
| `Frames` | `0` | 无界运行（出厂值，显式写一遍） |
| `Neural` | **`0`** | **第一轮只验传输**，神经阶段先不开，分离变量 |
| `AutoArm` | **`0`** | 手动 `Ctrl+Alt+F10`；自动武装容易在菜单里落地 |
| `Depth` | `1` | 传深度并绑定 |
| `MVec` | `3` | 传矢量并绑定 |
| `MVecSource` | **`1`** | 强制走 R280 的 G-buffer 抽取（A2 的一半） |
| `MVecUnits` | **`uv`** | 写死单位，排除"单位判决未定"这个变量（A2 的另一半） |
| `DepthTransport` | `1` | RE4 也没有 DLSS 表 ⇒ 拿不到渲染尺寸，只能用输出尺寸 |
| `DcompOverlay` | `0` | 先双屏自建窗口（不改硬件接线） |
| `ResidualPass` | `0` | 合成归属未定（mochizuki 自带 RenoDX stage，避免双重叠加） |
| `NRScale` | `0` | 同上 |
| `Passes` | `1` | x2 是功耗决定，先 1 |
| `Calib` | `2` | 默认；RE4 无 DLSS 契约，校准器拿不到东西，但留着不影响 |

## 7 · 部署脚本

```
pwsh -File  E:\AI\跨卡NR\08_工具与脚本\部署-MGPU到RE4.ps1              # 演练：只打印计划，不改任何文件
pwsh -File  ...\部署-MGPU到RE4.ps1 -Apply                              # 执行
pwsh -File  ...\部署-MGPU到RE4.ps1 -Apply -Undo                        # 回滚
```

**它做什么**：校验路径/来源 → 备份 + 写清单 → 停用 amd-nr → 改 `ReShade.ini` → 建 `reshade-shaders` + 放 tap → 拷 6 个文件 → 写 13 个 ini 键 → 假 NGX 拷两份 → 自检打印。
**它不做什么**：不启动游戏、不删任何东西（除 `-Undo` 时按清单删我们自己的部署物）、不动 `dxgi.dll` / `dinput8.dll` / `dlssnr_amd_*`。

脚本已演练通过（改动步数 0，路径与编码均正确）。注意两点：
- 用 **PowerShell 7（pwsh）** 运行；若只有 5.1，本脚本已存为 **UTF-8 with BOM**，控制台中文可能仍显示为乱码但逻辑不受影响（来源路径带中文，脚本会在 `E:\AI` 下自动搜索兜底）。
- 备份目录名是 `_备份-MGPU前-<时间戳>`，位于游戏目录内。

## 8 · 跑测流程与判据

**流程**：启动 RE4 → 进到**实际游玩**（不要停在主菜单/加载画面）→ 按 `Ctrl+Alt+F10` 手动武装。

**判据（按顺序）**

| # | 看哪里 | 通过的样子 |
|---|---|---|
| V1a | `[P7.10] AutoArm is OFF` | 出现（预期） |
| V1b | `[P4.0] stream arm hr=0x00000000 source=… slot=… ring=6 heap=…` | **武装成功** |
| V1c | `[SEAL] new f=… gap=1 … OK` | 连续 ≥3000 帧，`dropped/reordered/stale` 为 0 |
| V1d | `[T5] present loop alive: frame N` | 桥线程在出画 |
| V2a | `[R63]` 深度 lane | `sealed 100%`、`consumer bound > 0` |
| **V2b** | **`[R78]` 矢量 lane** | **`bound` 离开 0**（这是 A2 的胜负判据） |
| V4 | 把 `Neural` 改 `1`、重开游戏 | `[P4.1] CreateFeature(Reserved18) … Success` |

**一直 `HELD` 怎么办**：别反复按。看是哪一条——`[R63]` 是等深度（多半在菜单里，或 tap 没编译），`[R78]` 是等矢量（探针没发布速度缓冲）。两条日志都会直说。

## 9 · 回滚

```
pwsh -File ...\部署-MGPU到RE4.ps1 -Apply -Undo
```
它会：还原 `ReShade.ini`/`amd-nr.ini` → 把 `amd-nr.addon64.off-mgpu-*` 改回 `amd-nr.addon64` → 删除我们部署的文件（含 `mgpu\nvngx_dlssnr.dll`、`_nvngx.dll`、tap、7 文件中的可删项）。
不会删 `README.txt`/`LICENSE`/`mgpu\` 空目录（无害）。
