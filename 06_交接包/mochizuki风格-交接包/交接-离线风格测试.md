## 一、目标

在**离线**（不启动游戏）环境下，对 mochizuki 运行时设置不同的**风格/控制参数**，用同一帧数据各跑一遍，输出可视对比图，从而判断：

1. `NRStyle`（0=Default / 1=Natural / 2=Cinematic）的实际差异
2. `NRIntensity` / `NRLocalTone` / `NRLocalStructure` / `NRSkinStructure` 的效果
3. 这些差异是否值得在我们的跨卡代理里暴露成选项

**对比前提**：所有配置的**改动幅度（edit）要对齐到同一值**（之前用 **10/255**），否则比的是强度不是风格。

## 二、已确认的事实（都有实测证据）

### 2.1 风格参数在哪、怎么生效

| 键 | 范围 | 默认 | 含义 |
|---|---|---|---|
| `NRStyle` | 0/1/2 | 0 | Default / Natural / Cinematic（就是"风格预设"） |
| `NRIntensity` | 0~2 | 1.0 | 网络强度（与我们合成层的 gain 是两层） |
| `NRLocalTone` | 0~2 | 1.0 | 局部影调 |
| `NRLocalStructure` | 0~2 | 1.0 | 局部结构 |
| `NRSkinStructure` | -1~1 | -1.0 | 皮肤结构（需 `NRAutoMask=1`） |
| `NRAutoMask` | 0/1 | 0 | 自动人物/皮肤掩码 |
| `NRSkinIndependent` | 0/1 | 1 | 皮肤是否独立于局部结构 |
| `Style Grade` | — | 1 | 风格分级（等效 NVIDIA DLL 做法） |

这些键写在 `OptiScaler.ini` 的 `[DlssNr]` 段（或 `dlssnr-amd.ini`），**由前端读取**后通过控制块交给运行时。
我们直连 `LmxxfNrGetApi` 时**前端不存在** → ini 完全无效（和 `Model` 键一样的情况）。

### 2.2 运行时导出的控制函数（不在 136 字节 ApiTable 里）

```
MochizukiNrGetControlDefaults
MochizukiNrSetControls          ← 签名已确认：(ctx, ptr)
MochizukiNrGetFeatures          → 返回 1
MochizukiNrGetInfo              → 传错参数会崩（SEH 可捕获）
MochizukiNrSetExposure
```

**已确认的签名（探针 v4 实测）**：

```
SetControls(ctx, ptr)            → 所有 struct_size 都返回 0（不校验尺寸）★ 正确形态
SetControls(ctx, ptr, size)      → 不成功
SetControls(ctx, size, ptr)      → 不成功

GetControlDefaults(ctx, out, size) → r=0，但除了我们自己填的首 dword 外没有任何数据
GetControlDefaults(ctx, out)       → 同上
```

**重要推论**：
```
GetControlDefaults 返回的是【当前值】。
我们的直连路径没有任何前端设过值 ⇒ 当前值全 0 ⇒ "读不出东西"其实是"默认全 0"。
因此：风格字段的默认值和含义只能靠【试】来定位，不能靠读。
```

### 2.3 模型选择（顺带的重要机制）

`Model` 键同样由前端读，直连路径无效。但有一条**现成的强制切换办法**：

```
把 dlssnr-amd\dlssnr-small.bin 临时改名/移走
→ 运行时日志会打印：small model (caller) but ... is missing ...: original model
→ 自动退回旧模型 CC_SILVER_AARDWOLD(310.8)
→ 需要新模型时放回来即可（无需 API、无需 ini）
```

### 2.4 两种模型的实测基线（1080p，同一帧，20 帧平均）

| 模型 | 网络本体 | 基准整链 | edit（gain=1） | 锐度（gain=1） |
|---|---|---|---|---|
| 新 `CC_SMALL_FP8`（310.9） | 4.32 ms（p95 4.71） | 4.99~5.43 ms | 4.9/255 | +14.6% |
| 旧 `CC_SILVER_AARDWOLD`（310.8） | 10.68 ms（p95 11.49） | 11.67 ms | 7.3/255 | +10.1% |

参考：我们的合成增益是**线性**的，`edit = gain × 原始 edit`，所以对齐幅度不需要试错：
```
新模型：gain = 10 / 4.9  ≈ 2.04
旧模型：gain = 10 / 7.3  ≈ 1.37
```

## 四、必须知道的坑（都踩过，别重复）

### 坑 1：不要在 `build\Release` 里运行任何工具
那里有代理 `dxgi.dll`，会导致 `CreateDXGIFactory2` 失败（0x80004005）。
**统一在 `E:\AI\_归档\tmp\mochi_run` 里跑**，跑之前把 exe 复制过去。

### 坑 2：源码里不能出现中文路径 → `LoadLibrary` 报 126
MSVC 未加 `/utf-8` 时按 GBK 解释宽字符串，路径被打断。
**解法**：用 ASCII 联结 `E:\AI\_归档\mochi_bare`（已建好）：
```powershell
cmd /c mklink /J E:\AI\_归档\mochi_bare "E:\AI\跨卡NR\05_运行时与模型\mochizuki-裸文件"
```

### 坑 3：源码里不能有非 ASCII 字符 → 编译报 C2001 "常量中有换行符"
同样是 GBK 解析问题（UTF-8 中文字节里含 0x5C 会当反斜杠）。
**解法**：探针源码保持**纯 ASCII**（v3/v4 已经是）。若要写中文注释，需给编译器加 `/utf-8`。

### 坑 4：`__try` 不能出现在带析构对象的函数里（C2712）
`ComPtr` 函数里不能用 SEH。
**解法**：把 SEH 抽成纯 POD 辅助函数（见 `mochi_controls3/4.cpp` 里的 `CallSS / CallS2 / CallOO`）。

### 坑 5：`GetControlDefaults` 的"假命中"
它会把我们自己填进 `ptr[0]` 的 struct_size 原样留在缓冲区里。
判断"运行时是否真的写了数据"时，必须**跳过首 4 字节**检查。

## 五、下一步该做什么（按顺序）

### 步骤 1：给 `mochi_bench` 加 `ctrl.bin` 注入（**唯一的代码落点**）

在 `mochi_bench.cpp` 里，`PrepareSession` 成功之后、第一帧之前，加一段：

```cpp
// 读 E:\AI\_归档\tmp\mochi_run\ctrl.bin（例如 256 字节）→ SetControls(ctx, buf)
using SetCtlFn = int32_t(*)(void*, void*);
auto setCtl = (SetCtlFn)GetProcAddress(mod, "MochizukiNrSetControls");
FILE* fc = nullptr; fopen_s(&fc, "ctrl.bin", "rb");
if (fc && setCtl) {
    static uint8_t blk[256] = { 0 };
    size_t n = fread(blk, 1, sizeof(blk), fc); fclose(fc);
    int32_t rs = setCtl(ctx, blk);
    printf("[ctrl] ctrl.bin %zu 字节, SetControls -> %d\n", n, rs);
}
```
（`mod` 是 LoadLibrary 的句柄；`ctx` 是 Create 得到的会话）

# 九、本轮实测结论（2026-10-25 22:00，新对话接手后）

## 九.1 代码改动（都在 `mochi_bench.cpp`）

```
① ctrl.bin 注入：Create 之后、PrepareSession 之前调用 SetControls(ctx, blk)，
   会话建好后再调一次（运行时 uniform 走这一次）
② 修 GBK 坑：给 CMake target 加 /utf-8（否则源码里的中文路径被按 GBK 解释）
③ 修 fopen 坑：中文路径改用 _wfopen（/utf-8 之后 fopen 收 UTF-8 字节打不开）
   → 数据目录已改成宽字符串 kDirW
```

基线校验（改完之后）：新模型 1 遍 4.9/255、+30.2%；2 遍 9.6/255、+40.2% —— 与 §六 表一致。

## 九.2 SetControls 是真的（不是假命中）

| 输入 | 结果 |
|---|---|
| 全 0 块 + `ptr[0]=256` | edit **0.0000**（效果被完全关掉） |
| `ptr[0] ≤ 128` | **等同没调用**（回到运行时内部默认） |
| 全 1.0 块 | edit **21.5/255**、锐度 **−2.3%** |
| `ptr[0]=0` | 返回码 **2**（参数错） |

真实尺寸上限 = **0x20C = 524**（反汇编：`min(size, 0x20C)`，且要求 `size >= 4`）。

## 九.3 结构体布局（反汇编 `0x18001A720` 的 parse 函数得到，可信）

```
0x00 u32 struct_size（>=4，最大 524）
0x04 u32 未使用
0x08 f32 NRIntensity        限幅 0..2
0x0C i32 NRStyle            限幅 <=2      ← 0 Default / 1 Natural / 2 Cinematic
0x10 f32 NRLocalTone        限幅 0..2
0x14 f32 NRLocalStructure   限幅 0..2
0x18 f32 NRSkinStructure    限幅 -1..2，NaN/缺省 = -1
0x1C u32 NRAutoMask         非 0 = 开
0x20 f32 （限幅 1..8，缺省 1）—— 实测是【幅度主开关】，见 §九.5
0x24 f32 / 0x28 f32         未定
0x2C u32 ★★★ 总闸：非 0 才让上面这些字段生效 ★★★
0x30 i32 (<=2) / 0x34 i32 (<=30) / 0x38 i32 (<=2)
0x3C~0x84 空洞（parse 完全不读 → 扫偏移时这一段全是 inert，符合实测）
0x88~0xEC 扩展参数组（约 22 个活跃字段；0x94 限幅 0..6 缺省 3 很像
          PreprocessCurve 的 0..6，0x98 限幅 0.5..2 像 Contrast，
          0x9C 限幅 0.05..2 像 Saturation）
```

**★ 之前一直"改了没反应"的根本原因就是 0x2C = 0。** 只填头部字段、`0x2C=0` 时，
无论 style/tone/structure/intensity 怎么改，输出逐字节相同（0.0/255，等于关掉）。

## 九.4 两个错判（记录下来别再踩）

```
① `pre conditioning [style,tone,structure,skin,other]=[...]` 这行日志
   【不是】SetControls 的回显 —— 它来自运行时自己的 capture-controls 选项表，
   所以永远打印 [0,1,1,1,1]。拿它当 oracle 会白跑几十次。
② pipeline.cache / prewarm\manifest.txt 与风格参数无关：
   删掉它们重跑，输出 MD5 不变、耗时也不变（还是 2.1 秒），可排除"编译期烘焙"。
```

## 九.5 NRStyle 0/1/2 实测（同一帧，4K 底图，自动增益已对齐 10/255）

基准块：`intensity=1, style=?, tone=1, structure=1, skin=-1, automask=0,
0x20=2.0, 0x2C=1`（新模型 CC_SMALL_FP8）

| NRStyle | edit（原始） | 1 遍锐度 | 2 遍锐度 | 观感（目视） |
|---|---|---|---|---|
| 0 Default | 4.9/255 | **+30.4%** | +40.7% | 对比最硬、暗部压实、边缘带轻微锐化光晕 |
| 1 Natural | 5.4/255 | +20.5% | +19.2% | 最"平"：暗部被抬起、偏冷、细节自然 |
| 2 Cinematic | 4.9/255 | **−1.9%** | −1.6% | 最软、偏青/去饱和，像加了一层轻度降噪 |

三张输出图的 MD5 互不相同 ⇒ **NRStyle 确实改变观感，且三者差异是"风格"而非"强度"**
（幅度 4.9/5.4/4.9 基本一致）。

附带确认：
```
0x20（暂称 grade）: 1.0 → 0.9~1.3/255；2.0 → 9.1/255(锐 +32%)；4.0 不再变（饱和）
tone 2.0 → 幅度升到 1.5/255 且更软；structure 2.0 → 幅度降到 0.6/255
automask 0/1 差异很小（约 3%），skin -1/1 在无 mask 时没有差别
扩展组 0xAC~0xC8 全部填 1.0 → 4.8/255 但锐度 −2.1%（另一条通往"软"的路）
```
