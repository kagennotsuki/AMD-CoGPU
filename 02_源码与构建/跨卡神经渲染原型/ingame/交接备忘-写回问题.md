## 二、没解决的唯一问题：写回不可见

自证日志（`Invert=1` 时）：

```
nr-diff #1080: 抓回画面均值 191.3 | NR 输出均值 191.3 | 差 0.0     ← 那一帧生效
nr-diff #1200: 抓回画面均值 191.3 | NR 输出均值  63.7 | 差 127.7   ← 之后抓回游戏原图
```

含义：`writebacks` 计数在涨（4225 次），但后备缓冲里读到的仍是**游戏自己的画面**，
不是我们写进去的 NR 结果。

已排除：
- ❌ 交换链不对（只有一个窗口交换链被接管，`目标窗口变化` 从未触发）
- ❌ 格式不匹配（`bigOut` 已改成跟随交换链的 `R10G10B10A2`，问题依旧）
- ❌ 设备丢失（`deviceRemoved=0`）
- ❌ 合成交换链（有 HWND 过滤，`comp=0`）
- ❌ 命令列表未提交（`captured` 与 `frames` 同步增长，说明列表在执行）

剩下最可能的两条：
1. **`CopyTextureRegion` 到后备缓冲被 DXGI 忽略**：flip 模型下对 GetBuffer 返回的
   资源做整幅拷贝可能要求 `ALLOW_SIMULTANEOUS_ACCESS` 或不同的 state 约定；
   而 v3（每实例替换 vptr + 1080p 窗口）当时是**成功可见**的（负片验证过）。
2. **我们写的不是被呈现的那一块**：`GetCurrentBackBufferIndex()` 在 flip 队列有多帧
   在飞时，可能不是 Present 真正要翻的那一块。

## 三、下一步（v5，建议照测试台 1:1 搬）

`fake_game.cpp` 的那套流程是**已被证明可见**的（窗口里就是 NR 后的画面）：

1. **单一命令列表/分配器**，每帧一次提交一次 fence 等待（测试台这么做，480 帧零停摆）
2. **不加 held 写回**：有新结果才贴，但每帧都贴（测试台的写回率 100%）
3. **写回用 v3 的每实例 vptr 路径**（历史证明可见），只补抓帧的稳健性
4. 若仍不可见 → 退回 v3 代码（`dxgi_proxy_v2.cpp` 里 vptr 换法 + 1080p 窗口模式）
   先跑通"负片可见"，再往上加跨卡

## 五、环境事实（别再踩）

- 检查 GPU 侧改动前先看 `crossgpu.log`（已支持共享读，游戏运行中也能读）
- `.bat` 必须纯 ASCII + `%~dp0`；`.ps1` 必须 UTF-8 BOM
- 代理的导出**序号**必须与系统 DLL 一致，否则 `PDPerfPlugin.dll` 加载失败 → XeSS 全废
- Present 内**绝不等待** GPU（8ms 有上限的等待可接受，超过要跳过）
- 命令列表 Reset/Close 失败要**重建**命令对象，否则永久停摆

## 六、2026-10-24 凌晨续：上面那个「写回不可见」已经从根上绕过了（v7）

### 6.1 结论一句话

**交换链写回不可见这条线不用再修了**：改用 `libxess.dll` 代理后，画面根本不经过我们的交换链拷贝，
我们直接写 `pOutput`。而「NR 对画面没有改动」的真正原因是**网络结果根本不在 `fi.color` 里**，
而在 `job.private_output`；v3~v6 回读 `W.color`（逐字节等于输入）→ `edit ≡ 0`。
详见 `XeSS接口实测.md` 第十一节（含离线探针的硬数据）。

### 6.2 现在的状态

| 项 | 状态 |
|---|---|
| 结果来源 | `job.private_output`（`COMMON→COPY_SOURCE→COMMON`，Retire 前拷） |
| 网络输入 | XeSS 4K 输出 → 2×2 盒式下采样 1080p（探针证实 >1080p 会被 codec 拒绝） |
| 叠加到画面 | UAV 原地写 `pOutput`（零资源状态假设）+ UAV barrier |
| 跨卡数据 | 「本帧输出 − 本帧输入」的编码差分（`+128`，±0.5 量程、1/255 步长） |
| motion | 已接真数据（实测叫 passes 1→3、edit 峰值 0.17→0.40） |
| depth | 已接但默认关，实测当前惰性（等 history 才起作用） |
| history/carry | 未开（`hist=off`），是下一轮专项 |
| 安装 | 真身改名 `libxess_orig.dll`，代理放成 `libxess.dll`（游戏目录，已就位） |
| 还原 | 删 `libxess.dll`、把 `libxess_orig.dll` 改回 `libxess.dll`；或放 `xess_proxy_off.txt` 直接旁路 |

### 6.3 进游戏怎么自证（按顺序看日志 `xess_proxy.log`）

1. 看初始化：`outp 3840x2160 fmt=24 ... 可作 UAV=1`（必须为 1，否则一键旁路不会有 NR）。
2. 看 worker：`worker: private_output = 1920x1080 fmt=28` 且
   `worker: frame N 完成 xx ms | 网络 edit 平均 0.0xx 最大 0.xxx` —— **平均必须非 0**。
3. 看叠加：`stats: frames=... 叠加=... | 网络edit 平均...` 的「叠加」计数持续增长。
4. 画面自证：**F6**（增益 ×8）→ 画面应明显变化；**F3** → 左上角出现绿块（说明 dispatch 真的改到了 outp）。
   - F6 有变化、F3 有绿块 → 全链路通，调 F7/F8 找合适强度。
   - F6 没变化、F3 有绿块 → 差分内容为空（worker 侧没取到结果），看第 2 条日志。
   - F3 也没绿块 → UAV 原地写这条路在这台机器上不成立，回退方案见下。

### 6.4 如果 F3 都没绿块（唯一还需要回退的情况）

说明 `R10G10B10A2` 的 UAV 读改写在本机不可用，回退到 v6 的「SRV 读底图 + g_big + 拷回」路径
（`libxess_proxy_v6.cpp` 还在，`CMakeLists.txt` 换一行即可）。但**先确认日志里
`可作 UAV=` 是 1**，不是 0 —— 0 意味着 outp 没有 ALLOW_UNORDERED_ACCESS。

### 6.5 踩过的坑（新增）

- `build\Release` 里放着 dxgi/d3d12 代理 DLL：**在那里跑任何测试 exe 都会被劫持**，
  `CreateDXGIFactory2` 直接 E_FAIL（旧工具 `nr_*` 报错就是这个原因）。离线工具一律放 `build\probe_run\`。
- 探针写文件不能用中文路径（`fopen` 走 ANSI），输出目录用 `E:\AI\_归档\tmp\`。
- PowerShell `Get-Content`/`Set-Content` 往返会毁掉 UTF-8 源码（无 BOM 时按 ANSI 读），
  改文件用编辑工具或 Python 显式 `encoding='utf-8'`。
- `lmxxf` 会话一旦 fatal 就 `session is poisoned`，所有后续调用 UNAVAILABLE：探针必须一配置一会话。
