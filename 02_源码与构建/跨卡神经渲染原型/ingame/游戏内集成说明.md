# 游戏内集成说明（dxgi/d3d12 代理）

> 已在《生化危机2 重制版》实测：120~150 fps 下持续运行，跨卡 NR 每帧写回。

## 一、它做了什么

```
游戏（7900 XT）渲染 4K 帧
   ↓ Present 钩子（在游戏队列上提交，不等 GPU）
4K → 1080p GPU 下采样 → 回读缓冲 → CPU
   ↓ 工作线程（独立 D3D12 设备，建在 9070 XT 上）
传送到 9070 XT → LmxxfNrRuntime 推理（约 14ms）→ 回读 → CPU
   ↓ Present 钩子（下一帧）
1080p → 双线性放大到 4K → 贴回后备缓冲（一帧延迟）
```

关键设计：

| 设计点 | 原因 |
|---|---|
| Present 内**绝不等待 GPU** | 等待会与游戏队列时序互相卡死 → TDR |
| 两槽轮转 + 非阻塞收割 | 天然形成"一帧延迟"，且 Present 内零阻塞 |
| 按 `GetCurrentBackBufferIndex()` 取缓冲 | flip 模型槽位会轮转；写死 0 号槽会 `DEVICE_HUNG` |
| 只接管游戏主窗口那一个交换链 | 插件（libxess / PDPerfPlugin 等）会自建交换链 |
| 合成交换链（无 HWND）跳过 | 抓它必挂设备 |
| 每帧校验设备是否变化 | 游戏会重建 D3D12 设备，旧设备的命令对象提交到新队列会静默失败 |
| 命令对象自愈 | Reset/Close 失败时重建分配器+列表+fence |
| 导出序号与系统 DLL 完全一致 | `PDPerfPlugin.dll` 按序号导入 `d3d12.dll`，序号错会让 XeSS 整套失效 |

## 二、安装 / 卸载

```
ingame\安装游戏内集成.bat      # 拷贝代理 + 真实 DLL 备份 + 写 ini
ingame\卸载游戏内集成.bat      # 全部还原（系统 dxgi/d3d12 不受影响）
```

安装会放入：`dxgi.dll`（代理）、`d3d12.dll`（代理）、`dxgi_orig.dll`、`d3d12_orig.dll`、`D3D12Core.dll`。

## 三、配置 `crossgpu.ini`（游戏目录）

```ini
Log=1          ; 写 crossgpu.log（可实时读取）
Off=0          ; 1 = 完全不挂钩（安全旁路）
EnableNR=1     ; 0 = 只做 4K↔1080 缩放直通（排错用）
Invert=0       ; 1 = 反色（验证写回是否生效，会闪瞎眼）
```

## 四、实测数据（RE2，3840×2160）

| 指标 | 数值 |
|---|---|
| 游戏帧率 | 118 ~ 150 fps（带代理，未受明显影响） |
| Present 内提交 | **0.94 ~ 1.02 ms** |
| CPU 读回（1080p 8MB） | **0.44 ms** |
| 跨卡推理（9070 XT） | **14.1 ms/帧**（后台线程） |
| 写回率 | 约 85%（推理比帧时间长，每 ~5 帧一次更新） |
| 连续运行 | 8160 帧 / 73 秒，零崩溃、零设备移除 |

## 五、已知限制

1. **网络输入上限 1920×1080**：这是 `LmxxfNrRuntime.pak` 的硬限制（`QueryCapabilities` 报 max 1920×1080）。4K 必须下采样再放大。
2. **一帧延迟**：镜头快速移动时可能有轻微拖影（可用运动矢量补偿，尚未做）。
3. **放大是双线性**：4K 自身细节不损失，但 NR 的空间细节受 1080p 限制。更好的做法是"只把 NR 修正量叠加到 4K 原图"（已设计，未实现）。
4. **命令对象偶发重建**：约每 500~600 帧触发一次（某次 Resize 后列表进入错误态），自愈后继续工作，不影响画面。
5. **与 AMDNR 不能同时用**：AMDNR 也占 `dxgi.dll`，二者互斥。
